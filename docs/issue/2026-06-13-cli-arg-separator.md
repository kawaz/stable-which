# CLI 引数パーサの改善: `--` セパレータと値要求オプションの誤食い

- Status: open
- Date: 2026-06-13

## 背景

0.4.0 公開直前の総点検(QA / 初心者視点)で挙がった CLI 改善。0.4.0(ライブラリ公開 API 安定化)のスコープ外として保留。`cli-design-preferences` ルール該当。

## 課題

1. **`--` セパレータ未実装**: `cli-design-preferences` は「メイン引数との曖昧さ対策に `opts... -- args...` の `--` セパレータを用意する」と規定するが、現状の手書き引数パーサ(`crates/stable-which-cli/src/main.rs`)に未実装。
2. **値要求オプションの誤食い**: `stable-which --policy sh` のように、解決したいコマンド名 `sh` が `--policy` の値として消費され `unknown policy: sh` エラーになる。初心者は `sh` を解決する意図で打ちうる。

## 対応案

- `--` セパレータを実装し、`stable-which --policy stable -- <binary>` のように main 引数を明示可能にする。
- 手書き while ループの引数パーサを見直す。clap 導入も選択肢だが、依存追加(CLI のみ。lib の依存ゼロは維持)とのトレードオフを DR で判断する。

## メモ

- 0.4.0 リリース後に着手。CLI 出力設計(DR-007)/ CLI 改善(DR-012)の系譜。
- 実害は低い(値要求オプションの標準挙動ではある)ため優先度は中〜低。
